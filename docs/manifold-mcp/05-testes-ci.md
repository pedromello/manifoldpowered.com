## Gates proporcionais

- M0: Prettier/ESLint existentes e revisão focada de diff/DTO/metadata.
- M1: suite Jest completa existente + integrações MCP/caso de uso com PostgreSQL descartável. `.github/workflows/tests.yaml` já inclui novos testes via npm run test; não criar job/provedor separado por princípio.
- M2: `npm run typecheck:mcp` e `npm run build` passaram localmente; gates CI explícitos propostos para SDK/Pages/runtime, ausentes hoje. Typecheck geral mantém 15 erros antigos de testes; build Next filtra esses diagnósticos e não substitui o check de testes.
- M3: Inspector + ChatGPT real depois de hospedagem HTTPS/túnel autorizado; registrar protocolo, tools, inputs/outputs e requests negativos. Não é bloqueio de um PR documental nem prova já obtida.

Fixture e banco reais provam política e persistência sob controle local; SDK cliente prova contrato local. Nenhum desses demonstra descoberta/seleção de tools em ChatGPT, rede/proxy, elegibilidade no diretório ou catálogo editorial correto. Não usar número/cobertura como garantia.

Pipeline proporcional proposto: Node fixado no repo + npm ci → serviços descartáveis/readiness → Prisma generate/migrations locais → Next + Jest serial completo → lint/typecheck/build → teardown também em falha. O comando test atual usa migrate:dev; preferir migrations comprometidas com migrate:deploy ao melhorar o runner. posttest atual faz cleanup após sucesso, sem garantia em falha. Guardar dados/artefatos sintéticos. TRUNCATE do orchestrator só em DB local descartável; compose tem nomes/portas fixos, não compartilhar com outra frente. Não executar manutenção de features nem jobs de produção.

## PRIVATE no domínio — decisão mantida, correções autenticadas posteriores

Decisão: público nunca vê PRIVATE por slug/link; só criador/proprietário e admin podem acessar em superfície autenticada. Repo resolve proprietário pelo estúdio e admin por read:game:any; Game não registra autor individual original. Scope OAuth, biblioteca, publisher, afiliação e membership/ownership de Outlet não concedem acesso. 404 para ocultar existência é recomendação pendente. Plugin inicial não constrói caminhos privados.

## O que fixtures provam, e o que não provam

User/session/library criados pelo orchestrator provam política local e persistência, não login real do cliente OAuth, pagamento, intenção do jogador ou veracidade de feedback. `addToLibrary` prepara entitlement; E4 não passa por Stripe/processador externo. Nenhuma aquisição será tool do plugin.

Tokens assinados por chave efêmera + JWKS HTTP local provam verificações do nosso resource server se o código real as executa. Stubs que retornam claims válidas só exercitam a camada posterior. Um AS local controla descobertas, PKCE e revogação **simulados**; não prova configuração, propagação de revogação, CIMD/DCR/scopes/resource reais nem callbacks do ChatGPT. Provar assinatura não prova aprovação humana.

A jornada local com navegador prova UI/POST/versão/DB sob nosso controle. Só sandbox prova transporte do host, escolha de conta, OAuth reconnect, prompts, UI/elicitation e disponibilidade nas superfícies pretendidas. Registrar versão de protocolo/SDK/provedor, commit, inputs/outputs mínimos redigidos e resultado por cenário. Número de testes ou percentual de cobertura não substitui essas evidências.
