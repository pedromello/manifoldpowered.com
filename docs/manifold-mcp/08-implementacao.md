## O que foi entregue

- [Controller Pages Router](../../pages/api/mcp.ts): `/api/mcp`, runtime Node, bodyParser desligado, SDK com corpo máximo 32 KiB; Host/Origin permitidos derivam do origin da aplicação e loopback em desenvolvimento. Origin ausente permite cliente servidor-servidor; Origin/Host estranho retorna 403. Sem CORS wildcard, cookie/User injection ou cache HTTP.
- [Adaptador](../../infra/public_catalog_mcp.ts): duas tools `search_games` e `get_game`; `securitySchemes: noauth` por tool, espelhado em `_meta`; anotações read-only/idempotent, não destrutivas e openWorld. `structuredContent` e texto contêm a mesma projeção. SDK oficial `Server`/`createMcpHandler` cuida do protocolo; registro de baixo nível preserva a extensão OpenAI que o schema central de Tool remove. Nenhum protocolo/transport próprio ou camada genérica de tools.
- [Model do catálogo](../../models/public_game_catalog.ts): schemas Zod estritos, funções pequenas de validação, consulta, localização e projeção. Busca reaproveita `game.findAllPaginated`; slug usa consulta com ACTIVE/ONLY_DISPLAY, evitando o lookup público antigo sem filtro. Reaproveita `game_localization` e o filtro de saída do domínio, reduzido por allowlist própria. Não chama importer, pricing, compras ou APIs externas.
- [Typecheck MCP](../../tsconfig.mcp.json) e script `npm run typecheck:mcp`: verifica a composição nova e dependências importadas sem ocultar o check geral, que tem falhas anteriores. Workflows não foram alterados; `npm run test` existente descobre os novos testes.

SDKs fixados com lockfile: server 2.2.0 e node 2.1.0 em dependencies; client 2.2.0 somente devDependency para prova do contrato. Conforme [SDK oficial](https://github.com/modelcontextprotocol/typescript-sdk), v2 é a linha estável 2026-07-28; fallback stateless 2025 é deliberado. Não exige sessão, OAuth, profile ou elicitation.

## Contrato concreto

`search_games`: `q` string até 200 caracteres, default vazio; `tags` até cinco strings não vazias de 64 caracteres; `page` inteiro 1–100; `limit` inteiro 1–20, default 10; `locale` en/pt-BR, default pt-BR. Ordem fixa newest do domínio; texto case-insensitive em título/descrição/localização, tags OR. Zero resultados e página vazia são sucesso. Não há filtros de preço/status/conta; argumentos extras são erro.

`get_game`: slug não vazio até 255 caracteres e o mesmo locale. PRIVATE/INACTIVE/inexistente retornam o mesmo erro de tool `Game not found.`, sem conteúdo. Isso não escolhe 404 para todas as rotas web: a recusa MCP é `isError` no resultado de chamada conforme protocolo. Cookie/admin/Bearer enviado não amplia leitura.

Resultado factual: slug, title, até dez tags de 64 caracteres e launch_date ISO/null. Não sai descrição livre, mídia/URLs, requisitos arbitrários, IDs internos, status, usuários, reviews, preços/ofertas/checkout. Remoção de markup e URLs HTTP/www explícitas evita encaminhar esses elementos em título/tags; não é classificação editorial universal nem garantia contra qualquer texto adversarial. Não inventar opinião/experiência nem garantir disponibilidade comercial/legal. Contagem usa filtro público do domínio; concorrência não oferece snapshot congelado entre páginas/consultas.

Model: `search` e `findBySlug` compõem operações pequenas; controller/adaptador coordenam sem absorver autorização de negócio. Nenhuma transação de escrita é necessária à leitura; nenhuma fronteira de pagamento/giftcards foi alterada.

- Provas: ACTIVE/ONLY_DISPLAY positivos; PRIVATE/INACTIVE e slug conhecido negados; paginação/count, tags OR, localização e vazios; inputs bounded/extras; allowlist nas duas saídas; HTML/URLs explícitas removidos; cookie admin/Bearer sem privilégio; Host/Origin/body/malformed negativos; busca→detalhe→PRIVATE nega próxima leitura; contagem de User/Game/Review não muda pelas chamadas.
- Erro de model foi injetado no teste unitário e não expôs SQL/stack/credencial. Isso prova a fronteira de erro, não uma indisponibilidade operacional real de PostgreSQL. Jest emitiu aviso de operações assíncronas abertas no foco e na suíte completa; a causa não foi isolada. O comando completo terminou com sucesso e cleanup, sem afirmar que todos os handles foram encerrados pelo código de teste.
- `npm run lint:prettier:check`, `npm run lint:eslint:check` e `npm run typecheck:mcp` passaram. O typecheck geral com `--types node,jest` tem **15 erros anteriores idênticos à base**; comparação usa fonte original com o cliente gerado do schema inalterado, sem gerar/escrever arquivos no checkout original. Não são erros novos do MCP, e o check geral não foi considerado verde.
- **`npm run test` completo passou: 241 suítes, 1.540 testes, zero snapshots, 766,734 segundos.** Inclui os 29 testes novos. O posttest removeu os três serviços locais; não ficaram containers ou servidor Next desta rodada. - **`npm run build` passou**, compilou e incluiu `/api/mcp` como rota dinâmica. Isso verifica empacotamento local, sem deploy. O build não substitui o typecheck de testes: Next 16.2.3 [filtra diagnósticos de arquivos `.test`/`.spec`](../../node_modules/next/dist/lib/typescript/runTypeCheck.js), linhas 114–121; os 15 erros anteriores são nesses arquivos. O check MCP inclui explicitamente os quatro novos testes.

Logs locais de apoio: `/tmp/manifold-mcp-full.log`, `/tmp/manifold-mcp-focused.log`, `/tmp/manifold-mcp-build.log`, `/tmp/manifold-mcp-prettier.log`, `/tmp/manifold-mcp-eslint.log`, `/tmp/manifold-mcp-scoped-typecheck.log`, `/tmp/manifold-mcp-typecheck.log` e `/tmp/manifold-mcp-base-typecheck.log`.
